## Design Context

### Users
FileWeave users preview local and shared files within an Android file manager, including watching videos and listening to recordings or music without leaving the browsing workflow.

LAN sharing serves a quick handoff to Windows, Mac, or another phone: choose files or clipboard text, then scan or send one complete link through a messaging app. The user explicitly wants fewer paragraphs and clearer hierarchy on the sharing screen.

### Brand Personality
Simple, restrained, content first. Preserve the familiar Material Files experience and native Android controls.

### Aesthetic Direction
User confirmed on 2026-11-01: “简洁克制，跟随应用主题”. Audio follows the app’s light/dark theme and accent; video uses quiet, readable overlays over the picture. Keep existing system typography and Material icon language.

### Design Principles
- Keep video feedback near the bottom and leave the picture unobstructed.
- Give playback position, duration and primary transport controls clear hierarchy.
- Make touch targets accessible and reserve space for audio controls in the file browser.
- User approved a native UI rebuild on 2026-11-01: Android uses Kotlin, Jetpack Compose and Material 3 with restrained Expressive treatments, interoperating with established Views where needed. Mac uses SwiftUI/AppKit; a menu-bar left click must directly expose usable file operations, with a resizable standalone window as an option. Preserve the existing playback/data-source and security behavior.
- Communicate touch-control locking distinctly from vault encryption or device locking.
- On the sharing screen, make copying/sending the active link primary, keep content management secondary, and disclose detailed explanations on demand. Stopped and running states should have different action hierarchies.

- LAN sharing opens as a working phone-storage browser link by default. Show the active scope and a single link/QR handoff; keep optional scope changes and clipboard tools in menus. Links have no arbitrary time limit during the running service.

### Approved reconstruction direction (2026-11-01)
- Android navigation groups file browsing, paired devices, and transfer activity. File content stays ahead of history and administrative controls; file rows must not look like primary action buttons.
- Mac's menu-bar panel opens on useful file content and a compact connection/task overview. Recent recordings and received files are visible as activity summaries with secondary links; avoid four equal tabs. Device details live on demand, and secondary pages offer an explicit return to the preserved file location. Opening a standalone window is optional, not a prerequisite. The panel and window share workspace/task state. Capacity history belongs to device details and is disclosed on demand.
- Share product vocabulary and state meanings across platforms; use each platform's native typography, controls, navigation, keyboard and accessibility conventions.
- English is the initial product language. Offer English and Simplified Chinese with a persisted choice, including the browser-sharing experience. User filenames, clipboard text and transcripts remain unchanged.
- Validate real layouts with both languages, light/dark appearance, long filenames, empty/error/offline states, larger text and narrow/wide windows. Compilation is not visual acceptance.
