# 阶段任务

## M0：建立可维护的独立分支

- [x] 保留上游历史和来源版本。
- [x] 建立 main 分支，远端命名为 upstream。
- [x] 设置 FileWeave 名称、独立 applicationId 和开发版本。
- [x] 移除上游 Firebase 接入，保留许可证与作者署名。
- [x] 写入产品范围、技术路线和构建入口。
- [x] 跑通 debug 构建和 lint，记录实际结果。
- [ ] 真机安装，验证与 Material Files 同时安装、各自 Provider、分享和外置存储。

验收：可在同一设备独立安装；原有文件浏览和操作不回退；无上游 Firebase 接入。

## M1：普通视频和 Mac 文件访问

- [ ] 记录现有文件打开与网络 Provider 的随机读取路径。
- [ ] 接入内置播放器，先跑通本地视频及拖动。
- [ ] 支持字幕选择、音轨、进度记忆和播放错误反馈。
- [ ] 验证 Mac SMB 视频按需读取；避免整部视频下载后才播放。
- [ ] 完成 Mac 共享目录连接说明和断线提示。
- [ ] 使用系统分享调用 KDE Connect / LocalSend，未安装时提供说明。

验收：用代表性的 MP4 / MKV 与外挂字幕样本验证；大于 4 GB 文件可播放和跳转；断网、取消、权限失效和旋转不导致崩溃。测试结果需记录设备和 Android / macOS 版本。

## M2：加密技术原型

- [ ] 对比成熟格式及依赖许可，记录选型依据。
- [ ] 跑通创建库、密码解锁、文件导入和锁定。
- [ ] 验证加密大视频随机读取，检查缓存和缩略图。
- [ ] 定义锁定、后台播放与文件任务之间的会话规则。
- [ ] 验证错误密码、损坏文件、进程终止和空间不足。
- [ ] 验证 Mac 打开同一格式的加密库。

验收：锁定后旧读取会话失效；播放路径不先完整导出明文；单端修改、密文复制到另一端后可读取。未完成验证前不向用户承诺保险库安全性。

## M3：设备互通整合

- [ ] 根据 M1 的实际使用判断是否需要自己的 Mac 程序。
- [ ] 若需要：配对、设备列表、文件传输队列和收件目录。
- [ ] Android 前台 / 快捷磁贴主动发送文本，Mac 端接收并复制。
- [ ] 测试双向文本、重复消息、循环回传、离线与撤销配对。
- [ ] 明确剪贴板开关、过期和敏感内容策略。

验收：不依赖 Root 或 ADB 特权完成主动发送；未配对设备不能传入文件或剪贴板；重连不重复应用已过期内容。

## M4：发布准备

- [ ] 确认最终 applicationId、名称和图标。
- [ ] 增加分支关于页面、自己的隐私说明和发布地址。
- [ ] 维护 GPL 源码提供、依赖许可和第三方署名。
- [ ] 配置签名与发布流程，完成存储和视频真机回归。

每个阶段先交付可验证的行为，再扩展下一阶段；本次立项不代表 M1–M4 已实现。
