# Android 菜单审查与交互规范

审查日期：2026-11-01。范围：Android 文件浏览、选择模式、分享、文本/图片/视频预览和音频队列。

本文保留改造前的源码审查结果，并规定后续菜单的交互行为。已落地范围见下节，验证边界见 `VALIDATION.md`；未验收的条目不视为通过。既有主题、系统字体、Material 图标及 Kotlin / Views / ViewBinding 架构继续沿用。Mac 菜单栏不在本次审查范围。

## 当前实现（2026-11-01）

- 目录更多菜单收敛为全选、刷新、筛选文件、分享此文件夹、文件夹工具、转到路径六个入口，按最近文件/选择器状态筛选。保险库补充侧栏入口，原有局域网和 Mac 共享主页沿用侧栏入口。
- `ActionPanel` 使用同一 `BottomSheetDialog` 的层级栈显示目录、单文件、多选、编码与队列操作。标题返回与系统返回均先退一级；根层返回关闭，短页按内容收缩，长页滚动。页面离开或重建时安全关闭。菜单状态、作用对象和回调不绑定可复用的文件列表条目。
- 视图和排序使用连续设置对话框，模式/排序字段用下拉选择，详情/隐藏文件等保留开关；最近文件不提供手动排序。
- 格式入口复用筛选表单，后缀可输入并提供常用格式建议；应用后生效，取消保留原条件。
- 编码页提供常用编码、全部编码与搜索；已有编辑内容时更换编码需确认，取消保留编辑和编码选择层。
- 音频队列条目操作与队列共用容器；取消清空回到队列，重排后显示更新的队列，返回不停止播放。
- 单层短菜单继续保留。返回流程的模拟器回归不等同于所有路径类型、多厂商设备、TalkBack 和折叠屏的完整验收。

## 2. 内部存储更多菜单方案

根层建议顺序：

1. 全选（有可选择内容且尚未全选时显示）。
2. 刷新。
3. 筛选文件…。
4. 分享此文件夹 →。
5. 文件夹工具 →。
6. 转到路径…。

“文件夹工具”内包含：复制路径、添加书签、创建桌面快捷方式、在终端打开、新建窗口。上下文不支持的能力不显示；临时不可用且有必要解释原因时才禁用并说明。

“分享此文件夹”沿用统一分享方式：Mac、局域网、其他应用，只列出该路径支持的方式。Mac 动作必须保留实际共享语义，不能承诺未经实现的目录上传或同步。

职责迁移：

- **显示隐藏文件**移至视图面板，与显示详情放在一起；保留现有生效范围，不顺带把全局设置改成目录设置。
- **向上**由已有面包屑承担；保留键盘可达路径，不能只剩手势或长按入口。
- **局域网分享主页、Mac 共享主页**使用已有侧栏入口。目录菜单仅保留针对当前文件夹的动作。
- **保险库主页**应先补齐明确的侧栏入口，再从目录菜单移走；不能直接移除唯一入口。
- **新建文件/文件夹**保留原有新建按钮，不重复放入更多。
- 移动或隐藏菜单项时保留现有快捷键语义，必要时独立注册按键命令；不能假定隐藏菜单项后快捷键仍有效。

最近文件是聚合视图，没有“当前文件夹”。最近文件更多提供全选、刷新、筛选文件、最近文件范围；隐藏分享此文件夹和文件夹工具。文件选择器只显示选择所需操作，不出现保险库、共享主页等无关导航。

## 3. 全局菜单规则

### 按作用对象组织

- 页面菜单处理当前页面/当前目录；条目菜单处理单个文件；多选菜单处理选中集合。文案明确“此文件夹”“选中的 N 项”，不让用户猜作用范围。
- 应用级页面放侧栏，显示与排序放视图入口，筛选放筛选入口。入口可以提供任务快捷方式，但不重复整套主页导航。
- 常用文件动作直接可达；低频动作使用具体类别名，如“文件工具”“分享与发送”，不叠加“更多 → 其他 → 高级”。
- 一级动作菜单目标 5–7 项，超过 8 项必须重新审查；这是项目设计目标，并非平台硬性限制。文件条目既定 9 项可暂留，但不继续追加。
- 每组通常 2–4 项，用分隔线区分整理、工具、破坏性动作；避免每行一个分组。
- 动作分组最多两层。大量数据选项（编码、文件格式、播放队列）使用可搜索/滚动的专用选择界面，不继续加深菜单。
- 同一动作在单文件、多选和目录菜单中保持名称与分组一致。删除独立置底；清空队列等破坏性动作也单独分组，并遵循现有确认机制。
- 条件筛选先于分组：只读、压缩包内部、最近文件、空目录、外部选择器分别按能力显示。隐藏不支持项，避免出现空分组、空子菜单。
- 简单单层菜单继续用原生 PopupMenu；包含分层或大量选项的菜单采用下述容器。统一的是规则，而不是强行替换所有控件。

### 有下一层，就必须有返回路径

窄屏采用同一个 Material 操作面板（建议 `BottomSheetDialogFragment`），宽屏可用同一内容的对话框/浮层。内部以 Views / ViewBinding 切换内容，使用公开 API，不依赖 AppCompat 私有弹窗行为或反射。

二级标题栏示例：`← 分享与发送`；首层也显示当前文件名/目录名作为作用对象。返回图标需有“返回文件操作”等无障碍描述，触摸目标至少 48dp。

| 用户操作 | 必须发生的行为 |
| --- | --- |
| 一级点击类别 | 同一容器进入二级；保留父层滚动位置、焦点与作用对象 |
| 二级点标题返回 | 返回父层；焦点恢复到刚才进入的类别 |
| 二级系统返回键/返回手势 | 与标题返回相同；绝不顺带退出选择模式、切换目录或退出页面 |
| 一级系统返回 | 关闭面板，回到原页面 |
| 点面板外/下滑关闭 | 关闭整个面板；不执行动作，不改变文件选择或筛选条件 |
| 二级打开操作表单/确认框后取消 | 回到发起操作的层，保留输入草稿或原状态；不要求重新打开根菜单 |
| 完成一次性动作 | 按动作关闭面板并反馈结果；失败给出可恢复操作，不伪报成功 |
| 调整视图等连续设置 | 面板保持打开，立即显示新值；关闭时不再重复触发动作 |
| 旋转/窗口尺寸变化 | 恢复层级、作用对象与选中状态，或安全关闭；不得自动执行挂起动作 |
| 路径已失效/文件被删除/保险库锁定 | 重验动作能力，安全关闭或解释失效；不使用旧对象继续操作 |

状态由 Fragment 生命周期内的控制器维护，至少包括菜单来源、作用对象、层级栈与父层滚动位置；控件本身不作为状态来源。打开动作时重新检查对象是否仍有效。一次只存在一个菜单容器，避免父弹窗 dismiss 后又创建无父层记录的子弹窗。

`file_item.xml` 的二级结构用于动作分类；呈现与返回由 `ActionPanel` 承担。不能把标题不可点击的系统子菜单视为已经满足返回规范。

## 4. 视图、筛选与数据选择

- **视图和排序**：在一个分区面板中展示视图模式、显示详情/隐藏文件、排序字段/方向/目录优先、设置适用范围。当前值可见，可连续调整；最近文件隐藏手动排序并说明其固定新增时间顺序。现有“仅用于此文件夹”具体控制的设置范围须准确说明，不能暗示所有全局开关都会变为目录专属。
- **筛选**：复用现有类型/后缀、范围、日期表单；先编辑草稿，点应用后整体生效，返回/取消不改已生效条件。“清除格式”和“重置所有筛选”须明确区分，避免只想清除格式却丢失日期。现有快捷格式菜单的清除会重置整组 `SearchFilters`，改造时必须修正文案或行为。
- **编码**：显示当前编码，提供常用编码与搜索全部；选中后显示解码结果。编码改变需要重载文本时，已有未保存修改的处理规则继续生效，取消不得丢失编辑。
- **音频队列**：队列与条目操作使用同一层级容器；移动/移除后回到更新后的队列并尽量保持原位置。返回只影响界面，不停止播放；队列在操作期间变化时按条目身份重验，避免把动作作用到另一首音频。

## 5. 实施顺序与验收

1. 先完成带显式返回的公共操作面板，用单文件菜单验证。保留已确认顺序：复制、剪切、重命名、条件解压、分享与发送、存入保险库；工具区为打开方式、文件工具、属性；删除置底。
2. 精简内部存储更多菜单，补齐保险库侧栏入口，再迁移重复应用入口。
3. 重组视图/排序和筛选，统一目录、最近文件、搜索与多选模式的动作分类。
4. 将编码和队列接入适合的数据选择界面；保留短菜单。

每次实现应运行相关 Debug 构建与 lint；状态栈/动作路由等非平凡逻辑增加针对性的测试，简单文案/顺序不另写镜像测试。

UI 验收至少覆盖：

- 一级 → 分享 → 标题返回 → 工具 → 系统返回 → 一级 → 关闭，全程对象与选择状态不变。
- 二级表单取消回原层；确认删除取消不删文件；外部应用/选择器取消不更换原分享范围。
- 空目录、只读路径、压缩包内部、最近文件、单/多选和文件选择器无无关操作及空子菜单。
- 两次连续修改视图/排序无需反复重开菜单；取消筛选不覆盖原条件。
- 字体放大、TalkBack、横竖屏、窄屏/宽屏：返回始终可见/可达，标题和条目不截断关键含义，焦点顺序明确。
- 锁定保险库、文件删除或选中集合变化后，旧菜单不能执行越权或错对象操作。

实际执行的构建、测试与界面检查见 `VALIDATION.md`；本清单不是自动完成记录。
